# Pathway+ Placement Intelligence

Pathway+ is a full-stack placement workflow platform for students, employers, and administrators. It includes a React portal, an Express API, and persistent storage for local development or MongoDB deployments.

## Capabilities

- **Student portal:** profile management, job discovery and matching, applications, resume upload and analysis, skill gaps, a personalized learning roadmap generated from those gaps, roadmap progress, assessments, and notifications.
- **Company portal:** company registration, approval workflow, job posting, candidate matching, application management, and interview scheduling.
- **Admin portal:** platform metrics, user and company review, and employer approval.
- **Resume analysis:** PDF/DOCX text extraction, ATS-alignment and placement-readiness estimates, identified skills, gaps, and role suggestions.
- **Persistence:** MongoDB when `MONGODB_URI` is configured; otherwise a persistent local JSON database in development.

Resume analysis, job matching, readiness scores, and roadmap recommendations use transparent rule-based heuristics. They are not generated by a third-party generative AI model, do not guarantee hiring outcomes, and should be treated as guidance. Roadmap progress and account data are persisted. Uploaded resume files are processed in memory and are not retained.

## Requirements

- Node.js 20 or later
- npm
- MongoDB only when using MongoDB storage; local development defaults to the JSON file database

## Run locally

Open two terminals from the project root.

**Terminal 1 — API**

```powershell
cd backend
npm ci
npm run dev
```

The API listens on `http://localhost:5000`. With no `MONGODB_URI` in development, it initializes `backend/data/app-data.json` and a temporary development JWT secret. The database file is excluded from Git. Because the JWT secret is temporary, sign in again after restarting the API.

**Terminal 2 — web app**

```powershell
cd frontend
npm ci
npm run dev
```

Open `http://localhost:5173`. Vite proxies `/api` requests to the API at port 5000. The root-level `npm run dev` and `npm run build` scripts are also available.

## Environment configuration

Copy `backend/.env.example` to `backend/.env` when you need custom local settings. For MongoDB, provide `MONGODB_URI`. Production also requires a unique `JWT_SECRET` of at least 32 characters and a MongoDB connection string. Configure `FRONTEND_URLS` with the allowed frontend origins. Set `ADMIN_EMAIL` and `ADMIN_PASSWORD` privately to bootstrap an administrator; never commit `.env` files or credentials.

The API uses local JSON storage only as a development fallback. In production, it refuses to start if MongoDB or the JWT secret is missing.

## Validation

From the project root:

```powershell
npm run build
npm --prefix backend test
```

The backend tests cover resume text parsing and analysis/job-match calculations. The frontend production build validates Vite compilation and module resolution.

## API overview

All routes are prefixed by `/api`. Authenticated routes require a bearer token.

| Area | Routes |
| --- | --- |
| Health and realtime | `GET /health`, `GET /realtime` |
| Authentication | `/auth` |
| Students | `/students` |
| Companies | `/companies` |
| Administration | `/admin` |
| Jobs and applications | `/jobs` |
| Resume upload and analysis | `/resume` |
| Assessments | `/assessments` |
| Notifications | `/notifications` |

The concrete endpoints and role protections are defined in `backend/src/routes/`.

## Deployment

Deployment templates are provided for Render (`render.yaml`) and Netlify (`netlify.toml`). Before deploying, configure MongoDB Atlas, production `JWT_SECRET`, administrator credentials, and the frontend origin in the hosting provider’s environment settings. Update the API URL in `netlify.toml` if the Render service URL differs from the configured value. The templates do not create or configure those external services automatically.
